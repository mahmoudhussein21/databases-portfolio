# Reflection 01 — Introduction and Local-First Foundations

## Take-away

I learned how Git and GitHub work together and why SQLite is different from a server database such as PostgreSQL. Git commits save changes locally, while pushing sends them to GitHub. SQLite works inside an application without a separate server, and both SQLite and PostgreSQL can work offline.

## What was good?

I liked seeing my course files organized in a GitHub portfolio. Using Terminal commands and simple SQL examples helped connect the explanations to something practical.

## What was difficult?

At first I confused saving changes with Git and uploading them to GitHub. The difference between an embedded database and a database server also took some practice to understand. I still need practice with more advanced SQL queries.

## Exploration and show stoppers

I practiced working with a local project, SQL files, and Git commands. I learned why a `.gitignore` rule such as `*.db` keeps local database files out of the repository. The useful reminder for me is to check which changes are staged and committed before pushing.

## Interaction with peers and instructors

My Module 1 notes mainly cover my own practice. I can use the SQLite-versus-PostgreSQL example and the Git `add`/`commit`/`push` sequence to explain the basics to classmates.

## How did I check my work?

I used Terminal to check that my portfolio changes were committed and pushed. For database concepts, I compared the explanations with the actual commands and examples rather than only memorizing definitions.
